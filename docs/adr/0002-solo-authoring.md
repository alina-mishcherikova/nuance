# ADR 0002: Immutable quiz reads, secure solo attempts and private authoring

Accepted for stage 2, 2026-10-10. Stage 3 group transports and stage 4 publishing/admin remain absent.

The stage-1 relational schema is extended additively with solo guest sessions, question stable identities/configuration, version revisions and explicit approval/official/featured/archive markers. Stage-1 legacy enum values/nullable text column remain for compatibility; application validators accept only YES_NO_MAYBE, SINGLE_CHOICE, MULTIPLE_CHOICE and SCALE (1–5), never free text. Question/option translations and answers remain normalized. Only scoring configuration and immutable result snapshots use versioned validated JSONB.

Published reads require PUBLISHED + approved + an APPROVED moderation record + non-archived status + complete translations + eligible age access. New approved publication has database completeness guards. Official development seeds receive an explicit editorial review record through the local-only seed command. Authors cannot set approval, official status or publish. Existing published versions are never rewritten by repeated seeding or author edits; cloning creates new relational IDs while preserving question stable IDs, under a quiz-master row lock and unique version constraint. Pending review versions are read-only through author transports.

Solo guests hold one 256-bit verifier-backed, HttpOnly, SameSite=Strict credential, scoped to `/` because both server pages and API transports need it. HTTPS uses Secure; local HTTP is the deliberate development exception. Credential lifetime is fixed at seven days, not extended by reuse. An attempt identifier never proves ownership. Reads/writes independently query authenticated user ownership or an unexpired/unrevoked guest session and reject room attempts. Every attempt read/save/submit holds its row lock for a consistent answer graph. Revision checks reject stale saves. Final submit validates the full set, stores one uniquely constrained result and freezes the attempt. Repeated submission returns submitted status without replacing answers/result. Database triggers protect submitted answer graphs.

Both guest and registered solo attempts/results expire after seven days. This conservative registered-history policy is explicitly disclosed in the UI; extension needs a new policy decision in stage 4. Immediate service expiry is implemented, physical purge/backup deletion/user rights workflows are pending. User-created drafts persist until a future account deletion/retention workflow; do not use the development service for production personal data.

Solo algorithm `solo-profile-v1` reports counts, arithmetic means of scale answers by category and selected-option distributions keyed by immutable option ID. Rules describe the observed scale mean (<=2, >=4, or between), never compatibility/psychometrics. Pure `agreement-v1` primitives use exact match, 1–5 linear similarity, set Jaccard (both empty => 1), and normalized nonnegative weighted mean (zero total weight => 0). No group scores are generated yet.

The adult gate records a seven-day self-declaration on the verifier-backed guest session, also for authenticated browsers. It applies to catalog/detail/attempt/API/media and adult draft access; ungated public responses have no adult metadata. Self-declaration is suitable only for development; jurisdiction-specific legal review and production age assurance are blocked prerequisites.

New pinned dependencies are AWS SDK S3 3.1149.0 and Sharp 0.35.5. Uploads authenticate before reading a bounded raw body, match an allowlisted MIME to a signature, decode with pixel/time limits, resize/reencode to WebP without metadata and write random keys to a private bucket. Browser image reads use `next/image` with `unoptimized`, retaining cookie authorization and avoiding the optimizer's shared cache/auth omission. No remote URL ingestion or public storage policy exists. Production scanning, supported storage, quotas and orphan/media/account cleanup remain stage-4 hardening.

Development now uses webpack, matching the production build. The expanded catalog caused repeated Turbopack recompiles/navigation resets in this environment; webpack browser journeys passed. This changes no runtime architecture or dependencies. Auth forms now declare POST and disable fields until hydration to prevent native GET submission of credentials; author forms also declare POST.

Title ordering uses fixed EN/UK/FR ICU collations in PostgreSQL, with an ID tie-breaker and bounded offset pagination. Public responses remain no-store because adult eligibility is browser-specific; no shared age-sensitive cache is introduced. Parameterized search removes SQL wildcard/control characters, bounds input and applies conservative database rate limits without trusting incoming proxy IP headers.
