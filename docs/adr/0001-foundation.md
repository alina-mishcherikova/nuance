# ADR 0001: Foundation decisions (accepted, stage 1)

- **Modular relational monolith:** Next.js + PostgreSQL + pg/Drizzle. Foreign keys/checks/unique indexes protect integrity; relational permissions and translations; JSONB only typed immutable scoring/results. One deployment keeps authorization transactions coherent.
- **Auth:** maintained Better Auth 1.7.7, database adapter with transactions enabled, Argon2id (64MiB, 3 iterations, parallelism 1). Email OTP plugin with hashed codes, ten-minute expiry, five attempts; verification required; no social/passwordless sign-in endpoint. Database sessions and rate limits support multiple workers. Test library replay/revocation behavior against actual PG.
- **Guest ownership:** independent 32 random bytes, SHA-256 verifier only, room-scoped HttpOnly/SameSite cookie; Secure on HTTPS, seven-day maximum. Room code identifies a room and never authenticates a participant. Lost credential cannot be recovered by nickname. Revocation marker and expiry required.
- **Immutable quiz versions:** master/version split; unique master sequence and ordered children. DB triggers prevent mutation/deletion of published payloads. Moderated publication and complete translations validated transactionally in future stages; attempts retain version references.
- **Scoring:** versioned pure deterministic algorithms, Zod-validated configuration. Snapshot includes algorithm version and aggregate results; no solo compatibility invention. No scoring algorithm shipped in stage 1.
- **Retention:** guest data expires at 7 days with immediate service denial plus eventual physical purge. Registered retention remains pending product/legal policy; no history collection yet. Cascade only temporary dependent data, restrict published references; dedicated job in stage 4.
- **Media:** private S3-compatible storage, MinIO dev. No upload or export endpoint yet; later keys are unpredictable with signed limited access and reencoding.
- **Polling:** stage 3 authenticated no-store status polling with backoff avoids WebSocket infrastructure and simplifies per-request authorization. Status DTO cannot contain answers. Revisit only with measured load evidence.
- **UI:** original warm ivory/ink/terracotta token system, customized shadcn-style primitives with Radix accessibility; self-hosted/system sans to avoid external font calls. Theme and locale preferences only, no analytics.

References: [Next installation](https://nextjs.org/docs/app/getting-started/installation), [Drizzle PG](https://orm.drizzle.team/docs/get-started/postgresql-new), [migration workflow](https://orm.drizzle.team/docs/drizzle-kit-migrate). Registry versions and compatible peers are recorded in the exact lockfile. Development host Node 25 differs from Node 22 container/CI target; verification must report both honestly.
